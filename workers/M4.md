# M4 worker integrity and verification report

Status: implementation and local verification only. The completion target of two actual authorized providers settling and recovering without duplicate effects is **not achieved**. No teammate agreement, live receipts, refunds or UI confirmation is claimed.

## Implementation

New assignments require explicit immutable settings, pinned model/tokenizer and worker source identity, benchmark identity/hash/count, deadlines and chain identity. Downloaded bytes are SHA-256 checked before parsing. Duplicate IDs and excessive text/items fail validation. New successful results carry the complete specification in their identity; changed settings produce different cache paths. Submission and settlement reject mismatched configured chain/contract for new results. Contract encoding and existing durable broadcast/event/reveal/claim logic are preserved. Production evaluation uses an offline child with a 300-second kill/reap boundary.

2. Before inference, eligibility relies on authenticated backend assignment state, `finished=false`, provider identity and local commit deadline. Chain assignment and registered-wallet checks remain at submission/settlement. Independent pre-inference chain eligibility/deadline verification remains outstanding.
3. Legacy results remain recoverable under existing behavior to preserve pending settlements. They have no immutable specification guarantee. Use isolated new directories for M4 and audit old journals before enabling settlement recovery.
4. The current contract binds correctness vectors only, with no salt or specification binding. Matching vectors do not prove matching predictions. No ABI or protocol migration was attempted; any change requires shared encoding vectors and coordinated contracts/journals/worker documentation updates.
5. Two provider registrations, disposable funded wallets, matching exported image and architecture, live backend/RPC and a funded job remain needed. Record both commits/reveals/claims, sender authorization, acceptance, backend status and UI receipts. Repeat in fresh containers on two machines.

7. Memory/CPU/PID flags were added to the repeatability harness and documented for provider containers, but no Docker/cgroup run verified them. They are not enforced by the bare-host worker. Host exhaustion protection is therefore unproven. Startup warmup is outside the evaluation timeout; cancellation drains the child until it completes or hits 300 seconds. Container shutdown grace must account for this. Child loading temporarily duplicates parent model memory.
